How it works

Seven phases, each with a reference guide. The model reads code, understands your product, designs a site, builds it, runs it, looks at it, fixes what's wrong, then writes a short README.

  1. Investigate

    Read the entire repository — code, tests, docs, CI, migrations, TODOs. Reverse-engineer the real product.

    references/investigation.md
  2. Assess the stack

    Find existing design systems, brand identity, or color tokens. Use what exists; don't invent a parallel identity.

    references/stack.md
  3. Position

    One category, one audience, one problem, one differentiator, one value prop. These are settled before any copy is written.

  4. Design

    Define the design system — color, type, space, form — derived from the product's domain, not a template.

    references/design.md
  5. Build

    Section structure, scroll narrative, visual rhythm — implemented as real source files with no dependency sprawl.

    references/structure.md
  6. Verify

    Run the site. Render it at desktop, tablet, and mobile. Look at it. Fix the layout defects, contrast issues, broken links. Repeat.

    references/review.md
  7. README

    A short entry point that links to the site. Written last, kept brief.

What you get

Real source files. No build complexity. No framework bloat. One polished website.

Source files

HTML and CSS. Semantic markup, responsive layouts, reusable sections. No hidden dependencies.

Design system

Derived from your product's domain. Color, typography, spacing all intentional. Uses your existing brand if one exists.

Polished

Rendered at three widths. Visual hierarchy verified. Links checked. Contrast tested. Ready for visitors.

Deployment ready

GitHub Pages, a CDN, or static hosting. No backend needed. No build step required.

Honest copy

Every claim sorted by evidence first. Confirmed, partial, planned, or excluded. No invented metrics or customer logos.

Short README

Technical entry point. Links to the site, installation, architecture. Not a second copy of the website.

Install

The skill is SKILL.md plus five reference guides. Load it into any Claude instance running Claude Code, Cowork, or claude.ai with Skills enabled.

Claude Code / Cowork

# Windows PowerShell
iwr -useb https://raw.githubusercontent.com/scottconverse/landing-page/main/install.ps1 | iex

# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/scottconverse/landing-page/main/install.sh | bash

Or load the protocol manually

Copy SKILL.md and the references/ directory into your Claude environment's skills folder. The protocol works with any Claude model — no model-specific code.

Then invoke the skill

  • /landing-page
  • build a landing page for this repo
  • make this look legit
  • what does this project even do?

What it will not write

Hard exclusions. If the code doesn't support it, it doesn't reach the page.

  • Customer counts, usage numbers, adoption claims
  • Testimonials, customer logos, awards, press mentions
  • Benchmarks and performance numbers that were never measured
  • Uptime, reliability, or security guarantees
  • Production deployments or enterprise readiness that aren't proven
  • Roadmap dates and release timelines
  • Stock photography and fabricated screenshots
  • Dead placeholder links in the rendered page
